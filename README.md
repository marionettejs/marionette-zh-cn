## 从一个小改动开始，而不是先迁移整个项目

Marionette 5.0.0 已正式发布。它是一个结构化 JavaScript UI 库，核心不再依赖 Backbone、jQuery 或 Underscore。View 负责内容，Region 管理当前 View 的显示、替换和销毁；CollectionView 用于随数据变化的列表。

可以先打开官网的 Backstage 工作坊，让你的编程助手做一个很小的应用，再提出一个具体改动。这个入口使用 Marionette 5.0.0，不需要先创建本地项目。你的助手需要能够操作并展示浏览器；如果做不到，请让它说明限制，不要把“已生成代码”当作“已验证可用”。

给助手的第一条提示：

“请打开 https://marionettejs.com/#playground，阅读工作坊说明，用自带的 Marionette 5.0.0 做一个简洁的待办清单。支持新增、完成和按状态筛选。只使用演示数据，不读取我的文件或账户。完成后展示应用，并说明实际检查了哪些交互。”

接着提出一个小改动：

“在列表上方显示‘已完成 X / 共 Y 项’。统计全部任务，而不是只统计当前筛选结果。切换筛选或完成任务时，不要清空我正在输入的新任务文字。请实际尝试这些操作，再说明结果。”

验收时可以检查：

1. 新增三项任务，完成其中一项，显示‘已完成 1 / 共 3 项’。
2. 切换到‘未完成’，仍显示同样的总数，而不是把当前可见的两项当作全部任务。
3. 在输入框写一段尚未提交的文字，再操作其他任务，确认草稿没有被意外清空。
4. 使用中文输入法输入新任务，确认选择候选词时的回车不会误提交，确认输入后只添加一次。

以上是建议的检查步骤，不是已经完成的测试结果。工作坊页面说明草稿只保留在当前标签页，刷新会丢失；需要保存时使用下载。不要把私密内容放入演示。若选择导出到 CodePen，请先确认公开分享的内容，因为免费 Pen 是公开的。

## 继续开发

需要本地项目时，使用正式版快速入门，并明确固定 marionette@5.0.0 及所需同版本配套包。以安装版本对应的英文 API 文档为准，中文说明只作为辅助入口，不维护第二套实现。
